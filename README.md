# 孙学.skill

**先看自己站在哪里，再决定把故事讲多大。**

中文 · 6 个分析角度 · 4 种工作模式 · MIT

[技能入口](./sunxue/SKILL.md) · [场景示例](./sunxue/references/examples.md) · [图文小说](./sunxue/references/stories/my-tibo-godfather.md) · [来源说明](./sunxue/references/sources.md) · [下载 .skill 包](./dist/sunxue-v1.1.0.skill)

假设三家客户都说，每月五百元，可以考虑。

表格里已经有了一千五百元。

银行里还没有。

`sunxue` 希望模型先看见这个区别。

这是一个基于孙宇晨公开文字、访谈与传播案例提炼的中文 Skill。它帮助模型分析机会、利益、规则和注意力，把判断落到可验证的行动；需要写作时，再调用叙事方法。

它研究公开表达里能观察到的结构，不声称复原人物的私下思维。反证、分段投入和止损等方法是本项目补充的应用约束，不冒充孙宇晨原话。

## 先看它怎么判断

下面是合成测试场景，不是本项目的经营数据。

**输入：**

> 我想做一个对账工具。三家企业表示愿意每月付五百元，但还没有付款。每家每周需要一小时支持，服务器每月三百元。一个月按四周，我的时间按每小时一百五十元计算。该不该开始？

**孙学视角：**

> 先验证付费和交付成本。
>
> 三家全付钱，是每月 1,500 元。扣服务器，剩 1,200 元，还没算人工。
>
> 支持需要 12 小时，按给定价格计 1,800 元。
>
> 已列的月度账，差 600 元。开发、获客和税费还没有进来。
>
> 先确认交付范围，测试价格和支持方式。拿到实际付款与耗时记录，再决定是否开发完整版本。

它也可以判断应该进场、应该扩大投入。前提是说清楚：谁付钱，什么已经成立，什么还需要证明。

完整的 [四类示例](./sunxue/references/examples.md) 包括项目取舍、冷启动、事故回应和严格非虚构改写。

## 六个分析角度

这六项是项目的组织方式，不是所谓“孙宇晨亲授六条定律”。一次分析只选最相关的几项。

| 角度 | 先问什么 |
| --- | --- |
| **位置与机会** | 变化发生在哪里？你通过什么入口接触真实需求？ |
| **利益与兑现** | 谁付出、谁获益、谁控制分配、谁承担损失？ |
| **规则与路径** | 真正的限制来自哪里？替代路径是否可行、合法且付得起成本？ |
| **注意力与信誉** | 什么真实事件值得传播？关注之后，用户得到了什么？ |
| **未来与反证** | 什么条件成立才有上行？什么证据会推翻判断？ |
| **行动与退路** | 下一步怎样验证？投入上限与暂停条件是什么？ |

更多见 [决策模型](./sunxue/references/decision-models.md)。

## 四种工作模式

| 任务 | 输出重点 |
| --- | --- |
| 决策 | 明确判断、关键依据、可行行动、反证与退路 |
| 传播 | 受众、真实进展、可验证承诺、使用与信任的转化 |
| 写作 | 按素材选择场景、动作、数字、物件和留白；不新增非虚构事实 |
| 研究 | 核对原文、时间与材料类型，区分事实、自述、推断和未知 |

用户只要一百五十字改写，就不附商业分析表。事故回应需要交代的事实，也不会被“留白”省掉。

## 安装

把这段话发给支持 Skills 安装的 Agent：

~~~text
帮我安装这个 skill：https://github.com/MetaDC66/sunxue
技能目录是 sunxue/。请先确认当前工具支持的安装位置；如果已有同名技能，不要直接覆盖。
~~~

也可以下载 [sunxue-v1.1.0.skill](./dist/sunxue-v1.1.0.skill)。新版包含技能参考资料、《我的Tibo义父》全文和三张插图；[v1.0.0](./dist/sunxue-v1.0.0.skill) 保留供回退。它是包含 `sunxue/` 文件夹的 ZIP 格式压缩包：

- 当前工具支持 `.skill` 导入时，按其导入流程操作。
- 不支持时，用解压工具打开，或将扩展名改为 `.zip` 后解压，再按该工具的要求安装整个 `sunxue` 文件夹。
- 不要只复制 `SKILL.md`；按需读取的参考资料也属于技能。

不同 Agent 的安装位置和调用语法可能不同。本项目未测试所有客户端，不承诺通用的一键导入。下载仓库或压缩包本身不会自动安装。

## 使用

在支持 `$技能名` 调用的工具中，安装后可以这样点名：

~~~text
使用 $sunxue 分析这个项目。我有两万元、两周时间和一个人，应该先验证什么？
~~~

~~~text
使用 $sunxue 给这个产品做冷启动方案。不要虚构用户量、融资或合作，先列需要核实的事实。
~~~

~~~text
使用 $sunxue 改写这段经历。严格非虚构，不新增数字、对话和心理活动，只给正文。
~~~

~~~text
使用 $sunxue 起草事故回应。区分已确认事实、未知事项和已经执行的措施，不要代发。
~~~

~~~text
使用 $sunxue 的文学分支写一篇原创故事。参考《我的Tibo义父》的叙事方法，不复制它的人物、金额和情节；真实人物只使用已核实的公开背景，明确标注虚构。
~~~

不支持这种调用语法时，可明确要求 Agent 阅读 [SKILL.md](./sunxue/SKILL.md) 并按其中规则处理任务。

## 写作分支保留了什么

从《我的女友景甜》与上游写作 Skill 出发，重点保留：

- 能调动的资源，与无法控制的关系之间的反差。
- 叙述者知道的精确数字，与不知道的重要小事。
- 大事略过、小动作展开的节奏变化。
- 物件回返、称谓变化、旁人的日常流程。
- 事实清楚，意义留有余地。

不要求每篇都有巨额数字、空房间或死亡反转，不规定所有文章都必须短句和回环。孙宇晨的青年动员、商业评论、争议回应和小说，也不是同一种语域。参见 [写作方法](./sunxue/references/writing.md) 与 [传播方法](./sunxue/references/communication.md)。
